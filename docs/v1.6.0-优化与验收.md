# v1.6.0 优化与验收记录

日期：2026-09-15。正式发布基线为 `v1.6.0` 标签；尚未部署到真实 VPS。

## 本轮范围

完成现有 Bot 链路的优化，保留默认 20 GiB 本地预算、20 GiB 磁盘安全线、镜像摘要、
依赖版本以及 Bot 容器权限。未内置频道用户会话、115cli、OpenList 或双节点传输；
这些组合使用方式继续保留在项目记忆中。

| 方向 | 实现 |
| --- | --- |
| 监控隔离 | 资源、远端目录探测、调度各自循环；远端探测总超时 30 秒；采样过期不放行 |
| 基础健康 | 资源和调度双心跳，必须属于当前容器生命周期，不再复用上次容器的心跳 |
| 操作体验 | 私聊授权；持久 `/pause`、`/resume`；只读 `/doctor`；`/watch`；`/retry all`；`/confirm all`；手动 `/stream`；带二次确认的遗留文件清理 |
| 调度 | 流式与普通上传共享窗口；阶段吞吐、增长冷却、增长收益和本地积压反馈 |
| 恢复 | 数据库版本 1、合法状态迁移图、事务化迁移、状态变更记录、取消意图、独立临时／正式路径 |
| 文件安全 | 两个远端路径清理复验后才完成取消；正式文件变化时失败关闭；重命名后不重复上传 |
| 部署 | 隔离构建／预检；一致性 SQLite 快照；核对运行环境、代码指纹和双心跳；失败自动恢复代码、配置、数据库和旧镜像 |
| 实例建议 | 只读探测 CPU、内存、目标与 Docker 文件系统、inode、既有占用和 FUSE；提供均衡／流式优先存储值，部署前复检 |
| 备份治理 | 只读盘点、超过 5GB 提示、显式按类型保留最近 N 份；部署不自动删除回退点 |
| 扩展 | `MediaSource`、`Destination`、`UploadStream` 协议；服务构造函数可注入适配器 |
| 结构 | 命令路由、运维动作和用户状态展示移入 `bot_commands.py`，传输状态机继续留在 `main.py` |
| 构建 | 预检 Tcl/Tk；EXE 自检覆盖全部 payload 和隐藏 GUI 的创建／销毁 |

状态标签和额度归属集中在 `payload/app/states.py`；数据库拒绝未知状态和传输模式。
数据库历史只记录状态和时间，不新增文件内容、配置值或聊天内容的事件日志。
状态机仍以传输流程中的有序持久化为基础，并非引入通用工作流引擎。

## VPS 资源探测与存储建议

部署器测试 SSH 或点击“检测 VPS 并推荐”时，会在经严格校验的 `/opt/...` 安装路径上执行
固定只读探测脚本。探测结果使用版本化起止标记和字段白名单解析，避免把 SSH 欢迎信息当作
资源数据。建议同时考虑 CPU／内存档位、目标文件系统总量和可用量、已有 downloads 占用、
inode、受管 CloudDrive2 的 FUSE 要求以及安装／升级余量。

探测先读取远端 UID；非 root 用户通过现有 sudo 凭据执行同一只读脚本，避免因无法读取旧
安装目录而把已有占用误记为 0。`du` 和 `docker info` 都有短超时；统计失败时不生成建议，
不会把未知值降级为空盘。

源码默认的 20 GiB 本地预算和 20 GiB 磁盘保留线不变，探测不会自动覆盖表单。“均衡模式”
最多建议 20 GiB 本地预算；“流式优先”最多建议 8 GiB，并用于较小或可用空间较少的 VPS。
两种方案都按目标文件系统容量计算保留线，保留已有 downloads 所需额度。正式部署在任何远端
写入前重新探测并校验用户最终选择；内存、FUSE、inode 或空间不安全时失败关闭。

探测优先读取 Docker 报告的实际数据目录，无访问权限时回退到默认 `/var/lib/docker` 估算。
若 Docker 与安装目录分属不同文件系统，建议器会独立检查 Docker 空间和 inode；远端安装脚本
在 Docker 启动后读取权威目录并再次检查，然后才允许构建候选镜像。它只识别和验证，不自动
迁移 Docker 数据目录。

该功能不自动调整分区、扩容、格式化或挂载，也不把核心数转换为固定高并发。Bot 运行时仍由
现有动态窗口根据实时 CPU、内存、吞吐、错误率和积压收缩／增长。独立数据盘自动发现与迁移
没有纳入本轮，避免误选磁盘或破坏用户数据。

界面的“保守／标准／批量”性能档位只是说明：至少 2 核且约 4 GiB 内存为标准，至少 4 核且
约 8 GiB 内存为批量，其余为保守；它不会改写 CPU／内存阈值。存储建议才可由用户点击应用。

## 用户语义

- `/pause` 停止启动新传输，活动任务继续完成；已校验任务的清理仍可调度，暂停跨重启保存。
- `/watch` 最快每 5 秒编辑同一条消息；完成／失败或编辑失败即停止，重启需重新订阅。
- `/retry all` 每次最多处理 100 个失败任务，排除未完成的取消清理。
- `/confirm all` 每次最多把 100 个 `completed` 任务记为人工确认；该记录可选，不要求逐文件操作。
- `/stream <编号>` 可将排队或下载失败任务改为流式模式；`/orphans` 仅只读巡检远端临时文件。
- `/orphans clean` 只为当前巡检结果生成 5 分钟有效的一次性确认码；携码二次确认时重新扫描，
  活动任务同编号或已记录路径都会受到保护，逐项删除后复查；一次最多处理 100 项。
- 取消清理进行中不能用 `/retry` 抢占；取消失败后可再次 `/cancel`，或单独 `/retry` 撤销意图。
- 定时远端探测只读目录。目标子目录尚不存在时，可探测 WebDAV 根；真正创建目录发生在
  上传或主动验收时。目录可访问不代表可写，写权限仍由 `manage.sh verify` 主动验收。
- 下载、上传和流式管道分别显示速度；流式已送入管道的字节不等于远端已落盘。
- `completed` 仅表示 CloudDrive2 大小校验和本地清理完成；`confirmed` 仍来自用户 `/confirm`。

## 配置更新与程序升级

手工配置更新使用 `manage.sh apply-config /absolute/new-config.env`：
备份 `.env` → 临时文件替换 → 配置预检 → 仅更新 Bot → 等待健康 → 比较运行环境和代码指纹。
失败或可捕获的中断会恢复旧配置，必要时重新启动旧配置的 Bot；恢复失败明确报错。
SIGKILL、断电等无法捕获的中断仍需用保留的配置备份人工恢复。

`manage.sh check` 不显示配置值，也不写 WebDAV 文件。`restart` 不应用配置变化；
Compose 的 `up` 原本就支持配置变化时重建，不能把历史旧凭据问题单独归因于没有
`--force-recreate`。本轮通过运行配置比较来发现实际未生效情况。
[Docker Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)

完整程序升级仍通过部署器或 `remote_install.sh`。新版本先在隔离目录构建和校验配置，再备份
旧代码／配置并通过 SQLite Backup API 生成完整性已校验的一致性快照。提交后若 Bot 基础健康、
CloudDrive2 网络检查或运行配置／代码指纹核验失败，脚本会恢复旧代码、配置、数据库与旧镜像。
下载文件和 CloudDrive2 数据不复制进升级备份；断电发生在极窄的文件提交窗口时仍需使用保留备份人工复核。
部署结束只盘点备份；超过 5GB 时提示人工处理，不会自动删除。`manage.sh backups` 只读输出
三类备份的数量和字节数；`manage.sh prune-backups N` 仅在用户显式执行后删除各类型较旧文件，
N 必须为 1～50，其他文件不会处理。
升级前先 `/pause`，等待活动传输完成，另外备份持久数据；不要删除尚需恢复的 downloads。
更换目的账号或目标目录前，应处理完所有未完成和失败保留任务，避免相对远端路径指向新账号。
不要同时运行两个使用同一 Bot／数据库的实例，也不要盲目降级已迁移的数据库。

上传统计使用 rclone 的逐行 JSON `stats` 数据，客户端保留有界日志尾部并在取消／超时后
终止子进程。[rclone 日志与统计说明](https://rclone.org/docs/#use-json-log)

## 真实 VPS 的下一步验收

1. 备份持久数据，暂停队列并等待活动任务完成，再升级；确认部署返回成功。
2. 执行 `manage.sh check`，确认代码／配置一致和基础健康。
3. 配置 CloudDrive2 后主动执行 `manage.sh verify`，确认写入、改名、删除都成功。
4. 测试小文件、普通大文件、超过本地预算的流式文件和重启后的恢复。
5. 检查暂停／恢复、失败重试、取消清理、同名文件和磁盘接近安全线时的行为。
6. 最后在 115 官方客户端验证大小、可打开性；如需留档，使用 `/confirm <编号>` 或 `/confirm all`。

频道监听的后续接入应把授权来源送入同一个 TaskDB 和调度器，并增加来源类型、独立频道游标、
用户会话配置与历史补录规则。当前协议注入只提供接入边界，不等于已经具备多来源混合监听。
