# v1.6.1 更新与验收记录

日期：2026-09-15。发布基线为 `v1.6.1` 标签；本版本尚未由自动化流程部署到真实 VPS。

## 更新范围

v1.6.1 是 v1.6.0 的部署和 Bot 交互修订版，不修改默认 20 GiB 本地任务预算、20 GiB
磁盘安全线、镜像摘要、依赖版本、数据库架构版本或上传状态机。

| 方向 | 实现 |
| --- | --- |
| 管理页隧道 | 固定本机 `127.0.0.1:19798`，打开浏览器前验证真实 HTTP 响应，失效后自动重建 |
| 隧道诊断 | 区分本机端口占用、SSH 禁止 TCP 转发和远端服务无响应，不回退随机端口 |
| 状态页面 | `/status` 与 `/performance` 使用同一张四字标签单页状态卡片 |
| 快捷菜单 | 帮助页提供状态、队列、调度、诊断和只读临时巡检按钮 |
| 任务队列 | 每页显示 5 项，支持按钮翻页、任务直达和长文件名显示宽度截断 |
| 任务操作 | 详情页按状态显示刷新、重试、流式和取消；按钮取消需在 5 分钟内二次确认 |
| 权限边界 | 回调同时验证允许用户 ID 和私聊 chat ID，群组或其他账号不能执行 |
| 完成语义 | 日常界面统一显示“Bot 完成”，不再展示 115 人工确认提示 |
| 文档 | 补充 Windows 部署器填写、固定隧道、SSH 主机密钥变化和旧 VPS 覆盖升级说明 |

历史 `confirmed` 数据与旧 `/confirm` 处理器仍为数据库和已部署实例兼容保留；它们不会出现在
正常菜单、帮助、任务详情、完成通知和状态统计中。Bot 仍只验证 CloudDrive2 WebDAV 已接收
且远端大小正确，不宣称 115 官方端已经完成入库。

## 安全与恢复边界

- 按钮操作只接受配置用户在 Bot 私聊中的回调；无权操作只返回拒绝提示，不改变状态。
- 按钮取消的确认令牌只保存在内存中，5 分钟后或进程重启后失效；文字 `/cancel <编号>`
  为兼容保留原有显式操作语义。
- 取消仍先删除并复查本任务远端临时／正式路径，再删除本地副本；无法确认远端删除时失败关闭。
- 快捷“临时巡检”只读；删除 `.uploading-*` 遗留文件仍需 `/orphans clean` 一次性确认码、
  清理前重新扫描和逐项删除后复查。
- 固定管理页隧道只绑定本机回环地址，不对公网开放 CloudDrive2 管理端口。

## 升级方式

1. 在旧 Bot 发送 `/pause`，等待 `/status` 的当前传输归零。
2. 使用 `TG115-Deployer-v1.6.1.exe`，填写与旧实例一致的安装目录和配置。
3. 测试 SSH 后重新执行“一键部署基础环境”。
4. 部署成功后执行 WebDAV 验收，发送 `/start` 检查快捷按钮，再发送 `/resume`。
5. 在首次真实文件传输确认前保留 `/opt/tg115-backups` 中的升级回退点。

升级脚本会在隔离目录构建并预检候选版本，备份旧代码、配置和一致性 SQLite 快照；新 Bot
未通过健康、运行配置或代码指纹核验时恢复旧代码、配置、数据库和旧镜像。SQLite 任务数据库、
下载目录、日志、CloudDrive2 配置和挂载数据在正常覆盖升级中保留。

## 真实环境待验收

自动化测试不会使用用户凭据，也不会替用户部署 VPS。升级后仍应在真实环境执行：

```bash
cd /opt/tg115
sudo ./manage.sh check
sudo ./manage.sh status
sudo ./manage.sh verify
```

随后在 Telegram 检查快捷按钮、队列翻页、任务详情和取消确认，并用小文件、普通大文件及超过
本地预算的流式文件分别验证传输。最终是否已进入 115 官方端，应由用户在官方客户端确认。
