# v1.6.2 更新与验收记录

日期：2026-09-16。本版本尚未由自动化流程部署到真实 VPS；本地验证与 GitHub Actions、
真实环境验收的边界分别说明如下。

## 更新范围

v1.6.2 是部署器交付和 Bot 交互优化版，不修改默认 20 GiB 本地任务预算、20 GiB 磁盘安全线、
任务状态机、WebDAV 大小复验或失败回退语义。

- Windows 主部署器迁移到 PySide6，发布为 `TG115-Deployer-Modern-v1.6.2.exe`；保留 SSH
  主机密钥确认、VPS 资源建议、部署前容量复检、固定 `127.0.0.1:19798` 隧道、CloudDrive2
  网络修复和 WebDAV 真写验收，并增加离线预览、依赖诊断和脱敏日志导出。
- 增加 `TG115-Deployer-Classic-v1.6.2.exe`，保留原 Tkinter 界面作为低体积兼容版。两种版本
  使用同一套 payload 和配置语义；新界面功能优先在 Modern 版维护。
- `build.ps1` 支持 `-Edition All|Modern|Classic`，默认同时构建两个版本；构建时隔离 DLL
  搜索路径，避免开发机其他软件的 ICU 等同名运行库污染 PyInstaller 成品。
- Bot 快捷入口迁移到 Telegram 输入框左侧的原生命令菜单。新回复不再附带消息下方按钮；
  队列翻页和带任务编号的操作继续使用文字命令。
- 系统状态的目的端文案简化为“目标目录可访问”，不再显示“只读检查”和检查时间后缀；后台
  目录探测、采样过期保护以及 WebDAV 主动真写验收逻辑保持不变。

## 本地验证

发布提交前执行以下检查：

- 174 项 Python `unittest` 回归，无跳过，其中包含 4 项真实本地 rclone 回环 WebDAV 集成；
- Ruff 0.16.0、Bandit 1.9.4；
- `payload/requirements.txt` 与 `requirements-build.txt` 的 pip-audit；
- Modern、Classic 两个 Windows EXE 构建及各自的 `--self-test`；
- 工作流 YAML 解析、差异空白检查和必要文件清单复核。

以上结果覆盖本机源码、回环 WebDAV 和 Windows 打包，不代表已经完成真实 VPS、Telegram、
CloudDrive2 或 115 官方端验收。推送后仍以对应 GitHub Actions 运行结果为准。

## 从 v1.6.1 升级

1. 升级前向 Bot 发送 `/pause`，等待“实际传输”归零。
2. 推荐下载并运行 Modern 版；若电脑不适合 Qt 界面，可改用 Classic 兼容版。
3. 填写与旧实例一致的 VPS、Telegram、WebDAV、安装目录和部署选项。
4. 先“测试 SSH”，核对主机指纹和实例建议，再点击“一键部署基础环境”。
5. 部署器会备份旧程序、配置和一致性 SQLite 快照；任务数据库、下载目录、日志和 CloudDrive2
   数据目录继续保留。升级失败时按既有回退流程恢复旧版本。
6. 打开 CloudDrive2 管理页，执行 WebDAV 验收，再向 Bot 发送 `/start`、`/status`，最后用
   `/resume` 恢复调度并传输一个真实文件。

仅运行 VPS 上的 `manage.sh update` 不会从 GitHub 拉取新源码。首次真实传输确认完成前，
不要清理升级备份；TG115 只验证 CloudDrive2 WebDAV 已接收且大小正确，115 官方端仍需人工核对。
